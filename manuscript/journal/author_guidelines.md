# Ocean Engineering — Author Guidelines Checklist

Distilled from `Guide for authors - Ocean Engineering | ScienceDirect.pdf` (Elsevier, last updated Feb 2026). Use this as the pre-submission checklist; consult the PDF for full policy language.

## Scope fit (check before writing)

- In scope: ocean/naval/coastal/harbour engineering, offshore structures, wave mechanics, buoy tech, marine renewables, AUV/ROV, automatic control of marine systems, human factors in maritime safety.
- **Out of scope — do not submit:** marine engines/auxiliary systems, sediment transport/erosion, dam break, purely theoretical work with no ocean-engineering application, broad materials/corrosion studies without a naval/offshore focus, wind turbines without an offshore application, military-only applications.
- "Ocean Environmental Predictions" topic is scoped narrowly: only extreme-event prediction, extreme statistics, wave groups, tsunamis, short-term forecasts, and climate-change impact on structures/operations — **not** broader physical oceanography, climate modelling, remote sensing, or generic oceanic data analysis (send those elsewhere). This project's wave-spectra forecasting angle should be framed as short-term environmental prediction with a structural/operational engineering hook, not as climate science.

## Article type & length

- Original research paper: **≤ 40 double-spaced manuscript pages** including tables/figures.
- Discussion of a published paper: ≤ 6 double-spaced pages, submitted within 6 months of the original paper's online publication.
- Review articles are invitation-only — requires a Review Proposal Form approved by the Editors-in-Chief before submission.

## File format

- Editable source files only: `.docx` (Word) or `.tex` (LaTeX). **No PDF as source.**
- Word: single-column. Double-column only allowed for LaTeX.
- Remove strikethrough/underline unless scientifically meaningful.
- Figures: TIFF, JPEG, PDF, or DOCX. Tables: xls, xlsx, or docx. Equations: native Word math or LaTeX (editable text, not images).

## Section order (title page → references)

1. **Title page**: concise title (avoid abbreviations/formulae unless standard, e.g. DNA); full author given+family names in submission-system order; affiliations (superscript letters, full name + postal address + country); corresponding author clearly marked with email; present/permanent address footnotes if applicable (superscript Arabic numerals).
2. **Abstract** — ≤ 200 words (see below).
3. **Keywords** — 1–7, English, prefer single words (avoid "and"/"of" compounds).
4. **Highlights** (encouraged, not mandatory) — separate file with "highlights" in the filename; 3–5 bullets, ≤ 85 characters each including spaces.
5. **Main text**, numbered sections (1, 1.1, 1.1.1, 1.2, …); headings on their own line; abstract itself is not part of section numbering.
6. **Appendices** (if any) — label A, B, …; equations `Eq. (A.1)`, `Eq. (A.2)`, …, next appendix restarts at `Eq. (B.1)`; likewise `Table A.1`, `Fig. A.1`.
7. **Author contributions (CRediT)** — corresponding author lists roles per co-author (Conceptualization, Data curation, Formal analysis, Funding acquisition, Investigation, Methodology, Project administration, Resources, Software, Supervision, Validation, Visualization, Writing – original draft, Writing – review & editing). Not all roles need apply.
8. **Declaration of competing interests** — via the declarations tool at submission ("I have nothing to declare" if none).
9. **Funding sources** statement — standard phrasing: *"Funding: This work was supported by …"* or, if none, *"This research did not receive any specific grant from funding agencies in the public, commercial, or not-for-profit sectors."*
10. **Data statement** — state data availability (or reason it can't be shared) at submission. Research data policy **Option C** applies: must deposit data in a repository and cite/link it in the article, or justify why not.
11. **Declaration of generative AI use** — new section, placed **before the references list**, only if AI tools were used beyond grammar/spelling/reference checking. Template: *"During the preparation of this work the author(s) used [TOOL] in order to [REASON]. After using this tool/service, the author(s) reviewed and edited the content as needed and take(s) full responsibility for the content of the published article."* Omit entirely if nothing to disclose. AI tools must never be listed as an author.
12. **Acknowledgements** — separate section that must appear **directly before** the reference list (last body section, not on the title page or as a footnote).
13. **References**.

## Abstract rules

- ≤ 200 words, stand-alone (no forward references to figures/sections).
- State purpose → methods → main findings (+ statistical significance where relevant) → principal conclusions; emphasize novelty.
- Avoid citations; if unavoidable, give full author(s)+year.
- Define any non-standard abbreviation at first use.

## Units, formulae, tables, figures

- **SI units** required; give SI equivalents for any other unit used.
- Equations: editable text (not images), variables in italics, solidus `/` for inline fractions, powers of *e* as `exp`, numbered consecutively in order of first citation, displayed separately from text.
- Tables: editable text (not images); numbered by order of appearance; caption above/with the table; notes below the table body; avoid vertical rules/shading; don't duplicate data shown elsewhere.
- Figures: cite all in text; number by order of appearance; one file per figure with logical naming (`Figure_1`, `Figure_2`, …); caption = short title + description, minimal text, all symbols/abbreviations explained.
  - Vector drawings → EPS/PDF, fonts embedded or text-as-graphics.
  - Photographs (color/grayscale) → TIFF/JPG/PNG, ≥ 300 dpi (min width: 1063 px single column / 2244 px full page).
  - Bitmapped line drawings → TIFF/JPG/PNG, ≥ 1000 dpi (min width: 3543 px single column / 7480 px full page).
  - Charts/large tables → XLS/XLSX.
  - Annotated images → PPT/PPTX, embedded-image resolution ≥ 300 dpi.
  - Don't: submit low-res files, disproportionately small in-image text, or multiple plots merged into one file (exception: intentional before/during/after comparison panels).
  - Any AI-generated figure/image must be disclosed in its caption *and* in the general AI-use declaration; AI must not be used to create/alter primary experimental data images.

## Citation format (author–date, not numbered)

- In-text: 1 author → surname + year; 2 authors → both surnames + year; ≥ 3 authors → `First et al., year`.
- Multiple same-author-year refs get suffixes `a`, `b`, `c` (e.g., `2020a`, `2020b`).
- Groups of citations: alphabetical-then-chronological (or vice versa), consistently — e.g. `(Allan, 2020a, 2020b; Allan and Jones, 2019)`.
- Reference list: alphabetical, then chronological within an author.
- Journal names abbreviated per the LTWA (List of Title Word Abbreviations).
- Include DOIs where available.
- Reference list examples (Elsevier house style, comma before year, no numbering):
  - Journal: `Van der Geer, J., Handgraaf, T., Lupton, R.A., 2020. The art of writing a scientific article. J. Sci. Commun. 163, 51–59. https://doi.org/10.1016/j.sc.2020.00372.`
  - Book: `Strunk Jr., W., White, E.B., 2000. The Elements of Style, fourth ed. Longman, New York.`
  - Book chapter: `Mettam, G.R., Adams, L.B., 2023. How to prepare an electronic version of your article, in: Jones, B.S., Smith, R.Z. (Eds.), Introduction to the Electronic Age. E-Publishing Inc., New York, pp. 281–304.`
  - Dataset: `Author(s), year. Title [dataset]. Repository, version. DOI.` — prefix the whole entry with `[dataset]`.
  - Software: `Authors, year. Name vX.X (Version X.X) [software]. Repository. DOI.`
  - Website: full URL + accessed date.
  - Preprint: include the word "preprint" or server name + preprint DOI; once a peer-reviewed version exists, cite that instead.
- Every in-text citation must appear in the reference list and vice versa; abstract citations must be given in full.

## Ethics / declarations to prepare before submission

- Single named corresponding author (their affiliation alone determines OA/APC eligibility).
- Submission implies: not previously published (preprints/abstracts/theses OK), not under review elsewhere, approved by all authors and responsible institutions.
- Competing interests declared via the declarations tool.
- Generative AI use declared per section 7 above if applicable; AI cannot be a listed author.
- Inclusive language throughout; avoid unnecessary personal-attribute descriptors; prefer gender-neutral plural forms.
- Sex/gender-based analysis: if relevant, explicitly define how "sex" and "gender" are used (SAGER guidelines).
- Image manipulation: brightness/contrast/color balance adjustments OK only if no information is obscured/added; nonlinear adjustments (e.g. gamma) must be disclosed in the caption; no AI-based manipulation of primary data images.
- Maps: show only the actual study area (no larger bounding box than needed) and include the disclaimer that "map lines delineate study areas and do not necessarily depict accepted national boundaries."

## Submission checklist (final pass)

- [ ] Corresponding author designated, contact details current.
- [ ] All files uploaded: manuscript, figures (separate files, correct format/resolution), tables with captions, supplementary material, highlights file (if included), competing-interests declaration (.doc/.docx).
- [ ] Spelling/grammar checked; consistently American **or** British English (not mixed).
- [ ] Every in-text reference is in the list and vice versa.
- [ ] Permissions obtained for any third-party copyrighted material.
- [ ] Data statement included; data deposited in a repository and linked, or reason given (Option C).
- [ ] If OA: all authors aware they're responsible for the APC (unless covered by institution/funder).
- [ ] Section order matches the list above, with AI-use declaration (if any) placed before Acknowledgements/References, and Acknowledgements directly before the reference list.
